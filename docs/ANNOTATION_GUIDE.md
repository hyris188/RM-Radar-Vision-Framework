# 数据标注规范

本规范只描述标注格式与质量要求，不提供任何图片或标签。所有数据均需使用者自行采集和标注。

车辆和装甲板的类别体系及识别检测流程参考香港科技大学 ENTERPRIZE 战队 2025 年开源的 RM2025 Radar Algorithm 项目。

## 1. 通用目录与格式

检测任务使用 YOLO 归一化格式：

```text
<class_id> <center_x> <center_y> <width> <height>
```

所有坐标必须除以图像宽高，范围为 `[0, 1]`。图像与标签同名；无目标的有效负样本保留空标签文件。训练集和验证集不得出现同一原图、同一视频相邻重复帧或其增强副本。

## 2. 车辆检测

| ID | 类别 |
| --- | --- |
| 0 | `car` |

- 框住可见车体，不包含大面积阴影、反光和无关背景。
- 车辆被场地结构轻微遮挡时仍标注；无法可靠判断车体范围的模糊区域进入待复核集合，不作为负样本。
- 同一车辆只标一个框。

## 3. 装甲板检测与颜色

| ID | 类别 |
| --- | --- |
| 0 | `dead_armor` |
| 1 | `red_armor` |
| 2 | `blue_armor` |

- 框紧贴完整灯条/装甲板发光区域，红蓝类别必须按现实灯条颜色标注。
- 禁止根据 OpenCV 显示颜色猜测类别；先确认 Bayer 排列和 BGR/RGB 转换正确。
- 熄灭且仍可辨认为装甲板的目标标为 `dead_armor`。
- 反光、LED 屏、场地灯带和衣物图案不是装甲板，应作为背景或困难负样本。

## 4. 无人机检测

| ID | 类别 |
| --- | --- |
| 0 | `drone` |

- 框住无人机可见主体，螺旋桨运动模糊可包含在框内，但不要加入大片背景。
- 约一半被遮挡但仍能明确确认是无人机、且边界可一致估计时可以标注。
- 遮挡严重、身份不确定或无法稳定估计边界的样本放入待复核集合，不要直接当作确定负样本。
- 树叶、支架、灯具、文字、屏幕图案等易误检背景应采集为负样本并保持空标签。

## 5. 激光模块框与中心关键点

使用一类、一个关键点的 YOLO Pose 格式：

```text
0 <cx> <cy> <w> <h> <center_x> <center_y> <visibility>
```

| visibility | 含义 |
| --- | --- |
| 0 | 未标注/不存在 |
| 1 | 被遮挡但可推断 |
| 2 | 清晰可见 |

- 检测框覆盖完整激光模块。
- 中心点标在模块几何中心或项目统一定义的发射中心；全数据集必须使用同一规则。
- 中心不可判断时使用可见性 0，不得随意点击近似位置。

## 6. 装甲板数字分类

分类数据目录使用原始阵营类别：`B1`、`B2`、`B3`、`B4`、`BS`、`B0`、`R1`、`R2`、`R3`、`R4`、`RS`、`R0`。

训练代码映射为六类：

- `B1/R1 → 1`
- `B2/R2 → 2`
- `B3/R3 → 3`
- `B4/R4 → 4`
- `BS/RS → S`
- `B0/R0 → Q`

裁剪图应包含完整数字/图案，颜色不作为数字类别依据。不要使用水平或垂直翻转制造方向错误的增强样本。

## 7. 质量检查

每批数据至少完成以下复核：

1. 类别 ID 与 YAML 顺序一致；
2. 所有归一化坐标位于 `[0,1]`，框宽高大于 0；
3. 图像与标签一一对应，负样本具有空标签；
4. 训练/验证无哈希重复和相邻帧泄漏；
5. 红蓝装甲板在原始现实颜色下抽查；
6. 易误检背景拥有足够负样本；
7. 增强只应用于训练集，禁止把增强副本放入验证集。

可运行：

```bash
python preprocessing/validate_yolo_dataset.py \
  --dataset datasets/armor --classes 3

python preprocessing/validate_yolo_dataset.py \
  --dataset datasets/laser_module --classes 1 --pose
```
